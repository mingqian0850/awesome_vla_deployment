# 实时推理：时序与动作队列

[首页](../../README.md) · [English](../41-real-time-inference.md)

先按具体条件选择方案：[真机停顿与推理方式查表](deployment-decisions.md)。本页解释时序原理。

## 三种测量

| 指标 | 起点 → 终点 |
| --- | --- |
| 首个响应动作时间 | 观测到新事件 → 发出能够反映该事件的动作 |
| 观测到指令延迟 | 传感器采样 → 预处理、推理、解码与指令送达 |
| 动作块边界停顿 | 上一段动作缓冲耗尽 → 可用新指令到达 |

循环可以看起来没有停顿，却一直使用旧观测。任务需要及时反应时，应同时记录这三种量。

## 定义时序模型

设 `f_c` 为控制频率，`T_c = 1/f_c` 为控制周期，`H` 为预测步数，`s <= H` 为实际执行步数。`L` 是从观测采样到其首条指令可用的实测时长。需写清 `L` 是否包含传输、排队及执行器接口延迟。

```text
预测覆盖时长：       H * T_c
实际执行时长：       s * T_c
第 k 步的观测年龄：  L + k * T_c
```

观测年龄公式假设指令来自同一观测、等间隔执行，且从 `k = 0` 编号。额外排队或传输也需计入。该公式不是稳定性保证。

## 同步与重叠执行

**串行同步执行**先推理、再执行动作块、然后开始下一次推理。除非控制器另外提供过渡行为，否则每两个动作块之间都会出现推理等待。仅满足 `L < H*T_c` 并不能消除这段等待。

**重叠执行**在缓冲区仍有有效动作时启动新推理。若启动时还剩 `B` 秒可执行动作，则此次补充不耗尽队列的必要条件为：

```text
补充延迟 + 调度或传输抖动 < B
```

这是缓冲条件，不足以证明长期稳定、平滑或安全。调度器、动作替换规则和时间戳同样重要。连续多次慢推理仍可能耗尽缓冲。

**RTC**进一步以已承诺的动作为条件生成新动作块，改善衔接。仅启动异步工作线程不具备这一条件输入能力。Guided 与 trained RTC 对检查点和配置的要求不同，见 [LeRobot RTC 模式](resources.md#lerobot-rtc-modes)。

**时间集成（temporal ensembling）**混合覆盖同一时间步的多次预测。它可能减少跳变，也可能平均出不兼容的路径或增加计算需求。需在实测延迟分布下评测。

## 计算示例

示例取值：`f_c = 50 Hz`、`T_c = 20 ms`、`H = 10`、`s = 5`、`L = 76 ms`。

- 预测动作块覆盖 200 ms；实际执行的五步覆盖 100 ms。
- 第 `k = 4` 步使用的观测至少已过去 `76 + 4*20 = 156 ms`。
- 若补充推理启动时还剩 100 ms 有效指令，76 ms 的补充延迟只留下 24 ms 额外抖动空间；若补充耗时 120 ms，该缓冲就不足。
- 串行实现仍会在动作块之间等待推理。

增加 `H` 可以延长可用计划，但执行到更靠后的动作也会增加观测年龄。应结合任务评测分别调整 `H` 和 `s`，不要把示例步数当成硬件要求。

## 为一次执行添加测量

记录采样时间、观测组装、推理起止、队列插入或替换、指令发送或接收。使用同一时钟域，或记录时钟同步的不确定性。

将预热与稳态分开报告，记录延迟 p50/p95/p99 及样本量、队列耗尽次数、实际执行动作的最大观测年龄。同时记录有效控制频率与推理频率。

超时或输入陈旧时，调用已针对机器人和任务验证的响应。无限继续最后速度、保持某个力矩、打开承载中的夹爪和切断电源各有不同危险，应使用控制器文档规定的响应，不能套用通用回退动作。
