# 数据、动作约定与微调

[首页](../../README.md) · [English](../01-data-and-training.md)

## 采集前定义任务

写清任务指令、初始状态分布和可观测的成功条件。例如“把红色积木放进托盘”需要明确哪些放置情况算成功、何时结束 episode，以及如何标记失败尝试。

多阶段任务需要检查图像与状态能否区分各阶段。如果相同输入要求不同动作，就补充模型支持的历史、阶段标签或其他进度信号。当策略已有足够状态时，全局指令也可能足够，并非所有任务都必须逐子任务标注。

## 数据约定

| 字段 | 需要明确记录 |
| --- | --- |
| 相机 | 名称、视角、分辨率、通道顺序、时间戳约定 |
| 状态 | 维度顺序、单位、坐标系、缺失值处理 |
| 动作 | 绝对 / 增量 / 速度，关节或末端空间，夹爪开闭方向 |
| 时序 | 采样率、控制频率、观测动作对齐方式 |
| 语言 | Episode 指令，可选子任务或事件标签及边界 |
| 轨迹 | 起止、成功失败、人工介入、复位状态 |
| 归一化 | 方式、统计量来源、键名及关联检查点 |

大规模采集前先回放一个 episode。检查非预期空闲段、无效帧、关节跳变与末尾填充。覆盖记录应包含任务变化和恢复状态。Episode 数量、时长与多样性描述的是数据的不同方面。

使用[采集检查表](../../checklists/zh/before-collecting-data.md)与[日志模板](../../templates/collection-log.csv)。

## 归一化示例

设记录的关节数值 `x = 0.6`，均值 `mu = 0.2`，标准差 `sigma = 0.1`。Z-score 归一化得到：

```text
z = (x - mu) / sigma = 4
x_reconstructed = z * sigma + mu = 0.6
```

这只是计算示例。模型可能要求均值标准差、分位数、恒等映射，或对不同特征采用不同变换。需要检查最终构建的处理器及实际加载的统计量。

同时测试预期的正向数值和逆变换回环。若归一化及逆变换都直接返回输入，只检查回环仍会通过。对于分位数，各子数据集分位数的平均值不等于合并数据集的分位数。

统计量可以来自兼容的预训练机器人形态，也可以从训练数据计算。应记录选择并评测，不能默默替换检查点统计量。参考：[openpi 归一化](resources.md#openpi-norm-stats)、[归一化排错](troubleshooting.md#normalization-silently-skipped)。

## 做一次受控训练实验

1. 固定模型、代码版本与依赖，阅读匹配的配置和动作适配器。
2. 将评测 episode 或条件与训练数据分离，避免把同一轨迹的相邻帧分到两边。
3. 训练前检查最终配置与已加载权重。
4. 记录可训练参数名称与数量、batch size、精度、学习率和步数预算。LoRA 除 rank 外，还需记录目标模块。
5. 在试采集数据上训练，将权重、处理器统计量和配置一起保存。
6. 用同一任务协议评测多个检查点；在条件允许时，同时报告离线预测误差与闭环结果。

损失下降说明模型更好地拟合训练目标，不证明它正确理解指令、闭环控制稳定，或能泛化到新的相机位置。

## 阅读实验结果

| 现象 | 下一项测量 |
| --- | --- |
| 损失低但执行失败 | 检查动作含义、最终配置与实际访问的失败状态 |
| 离线预测几乎恒定 | 比较不同观测与采样随机种子 |
| 抓取位置正确但夹爪不闭合 | 检查适配器开闭方向与输出单位 |
| 遇到新物体就失败 | 分开测试物体覆盖、视觉变化与指令服从 |
| 只在保存时显存不足 | 单独测量保存检查点的显存峰值 |

**完成标准：**他人能根据记录还原输入输出约定，加载相同资料并运行相同评测。
