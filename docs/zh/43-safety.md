# 运行防护与故障处理

[首页](../../README.md) · [English](../43-safety.md)

## 分清职责

策略提出动作，机器人适配器解释单位与坐标系，控制器及防护系统约束允许的运行范围。学习式进度或失败监测器可以提供额外信号，但不能据此认定系统具备经过认证的安全功能。

| 层次 | 具体检查 |
| --- | --- |
| 硬件与工作区域 | 已验证的停止功能、人员进入控制、夹具和任务危险 |
| 指令接口 | 关节顺序、单位、坐标系、有限数值和支持的指令模式 |
| 运动限制 | 适合硬件的位置、速度、加速度和接触限制 |
| 时序 | 心跳、输入年龄、推理截止时间与队列耗尽 |
| 空间检查 | 可达工作区、自碰撞与夹具碰撞 |
| 接管与恢复 | 明确控制权、经过验证的恢复条件和人工接管 |

限制来自机器人、控制器和任务评估，而非示教数据分位数。监测器独立运行可以减少共享软件故障，但另开一个普通进程本身不等于安全等级控制器。

## 明确故障响应

为每类事件记录检测方式、响应、验证方法和重启条件。

| 事件 | 部署前需要定义 |
| --- | --- |
| 策略崩溃或 GPU 停滞 | 哪个独立组件检测故障并请求经过验证的停止 |
| 观测陈旧 | 最大允许年龄及超限后的响应 |
| 队列耗尽 | 没有有效指令时控制器采用的行为 |
| 越限 | 拒绝、限制还是触发停止，并记录每次事件 |
| 人工接管 | 哪些指令失去控制权，以及如何移交 |
| 重启 | 前置条件、状态检查与防止意外运动的措施 |

不存在通用“安全指令”。保持位姿、撤掉力矩、后退或松开物体可能带来不同后果。应针对机器人与负载选择并验证响应。故障注入先从模拟硬件或仿真开始，再按机器人操作规程进行受控真机测试。

## 日志与部署记录

保存观测时间戳、动作指令、防护事件、控制器状态与人工介入。使用[部署配置模板](../../templates/deployment-manifest.yaml)，将检查点与代码版本、机器人型号、标定、相机位姿、动作约定和归一化统计量绑定。

即使模型文件不变，标定或适配器变化也意味着部署系统发生变化。一次执行的日志应能识别全部关联资料。

## 标准与监测研究资料

[DGUV/IFA 协作机器人资料](https://www.dguv.de/ifa/fachinfos/kollaborierende-roboter/index-2.jsp)介绍防护措施与针对具体应用的评估。适用要求取决于机器人系统、用途及司法辖区。

[ISO 21448](https://www.iso.org/standard/77490.html)针对道路车辆的预期功能风险，可作为概念背景，但不是通用机器人认证规则。

研究监测器应报告检测延迟、漏检、误停、校准数据及评测条件。见[监测资料](resources.md#safety)与 [OGAM](resources.md#ogam-runtime-monitor)。

**完成标准：**面对心跳丢失或队列为空，能明确检测组件、已验证响应和重启条件。使用[部署检查表](../../checklists/zh/before-deploying.md)。
