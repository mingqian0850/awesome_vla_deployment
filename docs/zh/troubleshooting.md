<a id="only-first-action"></a>
## 只执行第一个子任务

### 1. 执行循环没有按预期消费动作块。

- **检查：** 记录动作块形状及每次推理后实际发送的指令数。
- **处理：** 显式设置执行步数，并对多个值进行评测。

### 2. 增量动作变换被重复应用。

- **检查：** 根据重建的关节目标核对数据动作含义和变换链。
- **处理：** 只执行一次增量转换，并在已记录样本上测试逆转换。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/issues/1047) · [↗ 2](https://github.com/Physical-Intelligence/openpi/pull/971)

### 3. 观测无法区分当前任务阶段。

- **检查：** 比较不同阶段的相似观测及各自所需动作。
- **处理：** 根据策略支持的接口，提供阶段标签、历史或其他可观测进度信号。

### 4. 状态输入恒定、尺度错误或未接入模型。

- **检查：** 检查各维统计量，并在图像固定时改变状态输入。
- **处理：** 使状态顺序、尺度和输入方式匹配检查点的实际配置。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0_config.py)

### 5. 预测动作几乎不随观测变化。

- **检查：** 比较不同观测与多个采样随机种子下的动作块。
- **处理：** 检查条件输入和可训练模块，再进行小规模受控训练评测。

### 6. 每条轨迹起始的空闲段影响了复位状态下的动作。

- **检查：** 绘制每条轨迹开始附近的动作幅度。
- **处理：** 裁剪非预期空闲片段，同时保持时间戳及观测动作对齐。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/blob/main/examples/droid/README_train.md) · [↗ 2](https://arxiv.org/abs/2503.06669)

### 7. 策略实际访问的状态缺少后续阶段示教覆盖。

- **检查：** 从中间状态启动评测，并检查各阶段覆盖率。
- **处理：** 补采恢复示教和后续阶段起始状态，再评测完整任务。

### 8. 归一化压缩了有效动作范围。

- **检查：** 逐维比较原始、归一化和解码后的动作，以及检查点统计量。
- **处理：** 在同一评测协议下比较兼容的预训练统计量与重算统计量。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/issues/763) · [↗ 2](https://github.com/Physical-Intelligence/openpi/issues/692) · [↗ 3](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/training/config.py)

补充来源: [↗ 1](https://mlanthology.org/corl/2025/jain2025corl-enabling/) · [↗ 2](https://arxiv.org/abs/2509.07953)

<a id="stalls-at-start"></a>
## 机器人在执行开始时迟疑

### 1. 记录包含非预期的起始空闲段。

- **检查：** 检查记录开始数秒内的动作与视频。
- **处理：** 调整录制边界，并一致地裁剪起始空闲段。

### 2. 第一次观测陈旧或不完整。

- **检查：** 在首次推理前记录各传感器的采样时间与有效性。
- **处理：** 在启用运动前等待有效且同步的输入，并预热推理。

<a id="stutter-and-stop"></a>
## 运动时走时停

### 1. 重规划与执行步数不匹配。

- **检查：** 绘制推理时间、执行步数及动作块边界的指令跳变。
- **处理：** 调整执行步数，并验证连续动作块的衔接方式。

### 2. 新动作到达前指令缓冲区已耗尽。

- **检查：** 比较推理启动时的剩余缓冲时间与实测延迟、抖动。
- **处理：** 在支持时使用重叠推理，并定义控制器允许的超时响应。

### 3. 动作含义或控制频率与训练阶段不同。

- **检查：** 检查绝对或增量约定、单位和指令时间戳。
- **处理：** 匹配策略动作约定，并显式适配控制器接口。

<a id="chunk-tail-garbage"></a>
## 动作块后半段错误

### 1. 轨迹末尾填充产生了错误训练目标。

- **检查：** 检查 episode 边界附近的目标与有效性掩码。
- **处理：** 使用模型支持的填充约定，并屏蔽无效目标。

### 2. 未来动作存在未消解的多种行为模式。

- **检查：** 将采样动作块与示教中的不同有效后续行为比较。
- **处理：** 改善阶段条件输入或缩短执行步数，再测量任务成功率。

<a id="ignores-instruction"></a>
## 改变指令不改变行为

### 1. 提示文本在分词前被丢弃。

- **检查：** 检查最终传给策略的文本与 token ID。
- **处理：** 修正特征名与观测变换，再测试含义不同的指令。

### 2. 全局指令无法标识当前子任务。

- **检查：** 检查相同输入是否在不同阶段要求不同动作。
- **处理：** 使用策略支持的子任务标签或历史，并确认标签实际进入模型。

### 3. 动作预测与语言条件耦合较弱。

- **检查：** 固定场景，多次要求选择不同的可见目标。
- **处理：** 检查数据任务相关性与条件输入，并单独评测指令服从能力。

<a id="fails-on-new-robot"></a>
## 换机器人后策略失败

### 1. 统计量缺失或与机器人形态不兼容。

- **检查：** 检查实际加载的均值标准差或分位数、单位及各维范围。
- **处理：** 使用兼容统计量，对比复用与重算结果，并检查必需字段。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/blob/main/docs/norm_stats.md) · [↗ 2](https://huggingface.co/docs/lerobot/en/pi05)

### 2. 关节顺序或动作维度不同。

- **检查：** 将原始动作、状态向量与机器人关节定义逐项比较。
- **处理：** 显式映射各维，并先在执行器禁用时测试映射。

### 3. 夹爪开闭方向相反。

- **检查：** 检查适配器约定，并在受控低风险测试中确认开闭方向。
- **处理：** 将约定记录在动作格式中，并只在接口处转换一次。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/blob/main/docs/norm_stats.md)

### 4. 相机视角或标定发生变化。

- **检查：** 比较采集画面、内参与外参与训练时的配置。
- **处理：** 恢复预期视角，或为新配置采集适配数据。

<a id="sim-works-real-fails"></a>
## 仿真成功而真机失败

### 1. 执行误差使机器人进入未见状态。

- **检查：** 比较专家状态上的预测与闭环执行结果。
- **处理：** 采集覆盖实际失败状态的恢复与介入数据。

### 2. 视觉或物理条件与仿真不同。

- **检查：** 在可行时分别改变光照、纹理、摩擦和柔顺性。
- **处理：** 用受控真机数据验证随机化仿真的结果。

### 3. 仿真没有建模部署延迟。

- **检查：** 测量真机从观测到指令的延迟，并注入仿真。
- **处理：** 修正时序架构，并评测延迟鲁棒性。

<a id="eval-numbers-not-trustworthy"></a>
## 多次评测的成功率差异很大

### 1. 评测样本较少。

- **检查：** 计算不确定性区间，检查独立试验数量。
- **处理：** 比较前固定试验协议，同时报告次数与区间。

### 2. 各轮初始条件不同。

- **检查：** 记录每次试验的物体位姿与任务变体。
- **处理：** 使用匹配的初始状态，并随机排列测试条件。

### 3. 评测期间温度或标定发生漂移。

- **检查：** 在评测开始和结束时重复同一参考条件。
- **处理：** 交错测试各条件，并记录温度状态与标定检查。

<a id="config-did-not-apply"></a>
## 配置修改没有生效

### 1. 加载权重没有恢复预期配置。

- **检查：** 加载检查点后打印最终构建的配置。
- **处理：** 针对固定版本显式传入必要设置，并核对运行时值。
- **补充来源：** [↗ 1](https://huggingface.co/docs/lerobot/en/pi05)

### 2. 归一化方式与参考配方不同。

- **检查：** 检查 ACTION、STATE、VISUAL 实际采用的映射。
- **处理：** 匹配检查点要求的变换，并记录有意保留的差异。
- **补充来源：** [↗ 1](https://huggingface.co/docs/lerobot/en/pi05)

### 3. 嵌套默认值覆盖了命令行设置。

- **检查：** 比较解析后的优化器、训练器参数与预期值。
- **处理：** 使用当前版本正确的参数命名空间，并保存最终配置。

### 4. 检查点包含旧统计量。

- **检查：** 比较实际加载的统计量与新计算的数据集统计量。
- **处理：** 通过受支持的检查点或处理器流程更新统计量，再次核对加载结果。
- **补充来源：** [↗ 1](https://huggingface.co/docs/lerobot/en/pi05)

<a id="normalization-silently-skipped"></a>
## 归一化被跳过或结果错误

### 1. 统计量键名与特征查找键不匹配。

- **检查：** 使用已知的非恒等统计量，同时检查实际归一化数值与逆变换回环。
- **处理：** 修复键映射；仅检查回环不能发现正反变换都被跳过的情况。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/4415)

### 2. 合并的分位数摘要不等于全数据分位数。

- **检查：** 将保存的边界与原始数据分位数、界外数值比例比较。
- **处理：** 在目标样本总体上计算分位数，并区分保守包络与真实分位数。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/4156) · [↗ 2](https://github.com/huggingface/lerobot/pull/3804) · [↗ 3](https://github.com/sawhney17/droid-quantile-repair)

### 3. 数据与机器人配置中的相机或特征名不同。

- **检查：** 逐项比较声明的特征与统计文件键名。
- **处理：** 在训练和部署前统一名称，缺少必需统计量时明确报错。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/1095)

### 4. 迁移流程错误改写了特征名。

- **检查：** 检查迁移后的统计量键名如何处理下划线和点号。
- **处理：** 使用策略声明的特征名与显式迁移映射。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/4451)

<a id="fine-tune-zero-success"></a>
## 损失下降但任务成功率接近零

### 1. 适配器目标遗漏了与任务相关的模块。

- **检查：** 检查实际可训练参数的名称和数量。
- **处理：** 与有效参考配置比较目标覆盖，并测试受控的适配器配置。
- **补充来源：** [↗ 1](https://github.com/Xbotics-Embodied-AI-club/Xbotics-Embodied-AI-Handbook/blob/main/docs/part3-end-to-end/12-VLA%E5%BE%AE%E8%B0%83%E5%AE%9E%E6%88%98.md) · [↗ 2](https://huggingface.co/docs/lerobot/en/smolvla)

### 2. 适配器目录被当作基础模型，或反之。

- **检查：** 分别检查已加载的基础检查点与适配器状态。
- **处理：** 使用所用版本对应的适配器新建或恢复流程。
- **补充来源：** [↗ 1](https://github.com/Xbotics-Embodied-AI-club/Xbotics-Embodied-AI-Handbook/blob/main/docs/part3-end-to-end/12-VLA%E5%BE%AE%E8%B0%83%E5%AE%9E%E6%88%98.md)

### 3. 多项设置偏离参考配置。

- **检查：** 比较完整的最终配置，包含统计量与动作步数。
- **处理：** 先建立参考基线，每次对比只改变一个因素。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/issues/711)

<a id="training-collapses-unexpectedly"></a>
## 训练出现 NaN 或异常损失尺度

### 1. 预训练权重没有正确加载。

- **检查：** 检查缺失键，并将已加载张量与检查点比较。
- **处理：** 固定兼容依赖，并在重新训练前验证权重加载。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/1406)

### 2. 动作方差接近零，导致尺度变换不稳定。

- **检查：** 检查各维方差及归一化后数值范围。
- **处理：** 显式处理恒定维度，并使用数值上适当的分母下界。
- **补充来源：** [↗ 1](https://github.com/Physical-Intelligence/openpi/issues/814)

### 3. 编译改变了数值行为。

- **检查：** 在启用和禁用编译时重复运行同一批数据。
- **处理：** 定位失败算子，并使用经过验证的编译配置。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/4178)

### 4. 恢复训练时未正确恢复适配器。

- **检查：** 比较恢复前后的适配器数值与可训练参数数量。
- **处理：** 使用兼容检查点格式恢复模型、适配器和优化器状态。
- **补充来源：** [↗ 1](https://github.com/huggingface/lerobot/issues/3459)
