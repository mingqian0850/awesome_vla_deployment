# 优化与评测

[首页](../../README.md) · [English](../40-optimization-matrix.md)

## 建立基线

运行原始检查点，记录任务成功率、试验次数、推理延迟与显存。比较改动时，固定任务、初始状态、相机输入、控制频率和动作含义。

| 测量项 | 应包含 |
| --- | --- |
| 延迟 | 计时范围、p50/p95/p99、样本量 |
| 任务结果 | 成功标准、成功次数 / 总次数、不确定性区间 |
| 显存 | 初始化、稳态及相关保存阶段的峰值 |
| 配置 | 模型与代码版本、精度、batch size、图像形状、相机数、预测执行步数、去噪步数 |
| 设备 | GPU 型号、功耗模式、温度、驱动与运行时版本 |
| 失败 | 漏抓、停顿、目标错误、防护介入及其他任务类别 |

区分冷启动、首次推理和预热后推理。除模型本体耗时外，还需报告预处理与端到端观测至指令耗时。

## 每次改变一个因素

例如编译、CUDA Graph、精度、图像处理、去噪步数或执行步数。每次改动：

1. 复用参考输入，比较输出动作。
2. 在相同计时范围下记录延迟与显存。
3. 使用匹配的任务试验，并交错运行条件以减小漂移影响。
4. 检查失败类型与动作连续性，不只看平均成功率。

随机策略应尽可能控制采样，并测量重复运行的变化。速度提高且离线动作相似，并不能单独证明闭环性能保持不变。

## 导出与量化

导出的计算图可能正常运行、输出发生变化，或因算子、动态形状和控制流失败。应把错误与配置保留在实验记录中。

在固定观测批次上，比较逐维动作绝对误差及任务允许的偏差，检查动作头和逆归一化。仅看余弦相似度可能掩盖重要的幅度误差或小动作误差。

低比特权重不保证 batch size 为 1 时延迟更低。算子支持、转换开销和访存都影响结果；[embodied-efficiency](resources.md#embodied-efficiency)记录了一个反例。

## 理解成功率

`9/10` 与 `90/100` 都是 90%，不确定性却不同。应报告分子、分母、初始状态协议和区间计算方法。对于相关 episode、重复复位或多任务测试，需说明独立样本的单位。

区分完整任务成功、子任务完成、指令服从和介入比例。可进行配对指令测试：固定场景，改变要求操作的可见目标，测量单一常规指令测试容易掩盖的行为。
